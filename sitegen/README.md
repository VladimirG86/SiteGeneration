# СБОРКА — прототип ИИ-конструктора сайтов (Фаза 0)

Рабочий прототип по модели VERSTKA.ai: анкета из 6 шагов → ИИ собирает лендинг
(структура, тексты, дизайн) → **ИИ-чат-редактор со структурными правками**
(вплоть до превращения лендинга в интернет-магазин с корзиной) → форма заявок.
Ключ RouterAI подключён через `.env` — всё работает на реальной модели.

## Быстрый старт

```bash
pip install -r requirements.txt
python3 -m uvicorn app:app --host 0.0.0.0 --port 8000
# открыть http://localhost:8000
```

`.env` (уже создан):
```
ROUTERAI_API_KEY=sk-...        # ключ из https://routerai.ru/settings/keys
ROUTERAI_BASE_URL=https://routerai.ru/api/v1
SITEGEN_MODEL=deepseek/deepseek-v4-pro-0813
```

## Генерация изображений

Этап «Рисуем изображения» работает через `POST /api/v1/images` RouterAI:

| Что | Модель | Цена | Время |
|---|---|---|---|
| Hero-фото по смыслу бизнеса (при создании сайта) | `bytedance-seed/seedream-4.5` (2K) | ~4.4 ₽ | ~10 с |
| Фото товаров каталога (параллельно, до 8 шт.) | `krea/krea-2-medium-turbo` (1:1) | ~1.6 ₽/шт | ~20 с |

Промпт для hero LLM сочиняет сама по описанию бизнеса (проверка «Brewhaus»: бариста
наливает латте, круассан на переднем плане — точно по брифу). У товара модель даже
вывела бренд на упаковку. Картинки сжимаются Pillow до webp (10–45 КБ) и встраиваются
в HTML как data URI — сайт остаётся самодостаточным файлом (~290 КБ с фото).
В чате: «Сгенерируй фото для товаров», «Замени фото на первом экране».
Настройка — `SITEGEN_IMAGE_MODEL` / `SITEGEN_IMAGE_MODEL_FAST` в `.env`.

## ИИ-редактор (главная фича)

После генерации сайт открывается в редакторе: слева живое превью
(десктоп/мобильный), справа чат. Клиент пишет словами — модель возвращает
**JSON-операции**, которые платформа применяет к структуре и перерисовывает сайт.

Возможности (проверены на живой модели):
- **«Сделай интернет-магазин»** → включает корзину, добавляет каталог товаров
  (фото/эмодзи, цены, бейджи), переписывает hero и меню под магазин + запускает
  генерацию фото товаров;
- **изображения**: «Замени фото на первом экране», «Сгенерируй фото для товаров» (op `gen_images`);
- тексты и структура: добавить/удалить/переставить секции, обновить услуги, цены, FAQ;
- дизайн: темы (light/dark × 6 акцентов) по просьбе «смени тему на тёмную»;
- мультитёрн: контекст диалога помнит последние 8 сообщений; на вопросы отвечает
  без правок (0 ops);
- **undo**: каждая правка — версия (до 12), кнопка «Отменить» откатывает
  структуру (файлы картинок пока не версионятся);
- корзина в магазине: счётчик, панель с количеством и суммой, оформление заказа
  → заявка попадает в `/api/leads` с `type: "cart"` и составом заказа.

Протокол операций (`chat.py`): `set_theme`, `set_info`, `set_nav`,
`upsert_section` (10 типов секций), `add_section` (второй блок того же типа),
`delete_section`, `move_section`, `set_feature(cart)`, `gen_images(hero|products)`.
Секции адресуются стабильным `id` (`prices`, `prices-2`) или `type` (первый блок);
дубли получают уникальные якоря (`#prices-2`), `hero`/`contacts` — только один. Модель НЕ рисует HTML — только
оперирует структурой, поэтому правки безопасны и дёшевы (~0.1–0.5 ₽ за правку).

## Демо-режим (без ключа)

**Без ключа работает демо-режим**: контент собирает встроенный генератор
(`demo_content.py`) — можно кликать всю воронку целиком (кроме чат-редактора).

## Подключение RouterAI (боевой режим)

```bash
export ROUTERAI_API_KEY="ваш-ключ-с-https://routerai.ru/settings/keys"
# опционально:
export SITEGEN_MODEL="deepseek/deepseek-v4-pro-0813"   # генерация сайта
export SITEGEN_MODEL_FAST="deepseek/deepseek-v4-pro-0813"  # подсказки-чипы
```

- **API:** OpenAI-совместимый, база `https://routerai.ru/api/v1`, эндпоинт
  `/chat/completions` — код уже написан под него (см. `llm.py`), менять ничего не нужно.
- **Оплата в рублях**, без VPN, инфраструктура в РФ (важно для 152-ФЗ).
- **Рекомендация по моделям** (точные ID и цены — в каталоге routerai.ru/models):

| Задача | Модель | Цена (вход/выход за 1М) | Зачем |
|---|---|---|---|
| Генерация сайта (JSON ~15–25К токенов) | DeepSeek V4 Pro 0813 | ~97/293 ₽ | ~6–8 ₽ за сайт, отличное качество текстов |
| Премиум-генерация и сложные правки | Claude Sonnet 5 / GPT-5.6 Sol | ~218/1093 ₽ | тонкая вёрстка, агентные правки |

| Чипы-подсказки | любая дешёвая/быстрая | — | мелкие JSON-ответы |

Ориентир себестоимости: **сайт в LLM-режиме ≈ 6–25 ₽** (один вызов + парсинг).

## Архитектура (почему так)

```
static/  — SPA-мастер + ИИ-редактор (vanilla JS, без зависимостей)
app.py   — FastAPI: /api/analyze · /api/generate · /api/import · /api/job · /api/site
                               /api/chat/{id} · /api/chat/stream/{id} (SSE) · /api/undo/{id}
                               /api/lead(s) · /api/auth/code · /api/auth/verify
                               /api/export/{id} (ZIP) · /api/publish/wp/{id}
generator.py — пайплайн 5 этапов (generate/import), версии правок (undo), история чата
importer.py  — перенос любого сайта по URL: fetch → extract_signals → LLM/эвристика → normalize_site
chat.py      — ГЛАВНЫЙ ФАЙЛ РЕДАКТОРА: промпт агента, 10 операций,
               id-адресация секций, sanitize/normalize (белые списки, лимиты) —
               защита от вольностей LLM
prompts.py   — промпты генерации/импорта и чипов + нишевые гайды (тон, якоря цен, FAQ)
llm.py       — клиент RouterAI (OpenAI-совместимый) + .env + извлечение JSON
images.py    — генерация изображений (/api/v1/images): hero + фото товаров,
               промпты, постобработка (Pillow → webp), кэш data URI
design.py    — дизайн-система: темы, CSS секций, каталога и корзины
sections.py  — библиотека рендера: hero/services/…/products + корзина (vanilla JS)
demo_content.py — демо-контент без LLM (и фолбэк при недоступности API)
niches.py    — банки чипов по нишам (фолбэк для /api/analyze)
sites/       — сайты: {id}.json (структура) + {id}.html + {id}.history.json (версии)
```

**Ключевое решение — гибридная схема** (как у VERSTKA.ai): LLM управляет только
контентом внутри жёсткой JSON-схемы, вёрстку делает детерминированный рендерер.
И генерация, и чат-правки оперируют одной структурой — поэтому редактор может
менять всё: от текста кнопки до превращения лендинга в магазин.

Сгенерированный сайт — **самодостаточный HTML** (~35–45 КБ с магазином): CSS и JS
встроены, иконки — инлайн-SVG/эмодзи, шрифты — Google Fonts с фолбэком.
Пример в корне: `sample-store.html` (магазин зоотоваров после правок чатом).

## Что взято из скриншотов VERSTKA.ai

1. **Воронка из 6 шагов**: О бизнесе → Продукт → Отличия → Тема → Пожелания → Проверка (стрелочный степпер с номерами и подписями).
2. **Модалка-помощник «Что написать?»** с блоками «Хорошо, если есть» (зелёный) и «Не нужно» (красный) + живой пример в курсиве.
3. **Чипы-подсказки** «Нажмите — добавим, а вы поправьте под себя» — подгружаются после анализа бизнеса на шаге 1.
4. **Обязательные/необязательные поля** с пометками, «Отмена/Назад» отдельно от градиентной «Далее →».
5. **Выбор темы карточками-превью** (светлая/тёмная с мини-вайрфреймом).
6. **Экран кода из письма**: 6 цифр, таймер повторной отправки (44 с), «Изменить email».
7. **Экран генерации** с чек-листом из 5 этапов и прогресс-баром (Анализируем → Проектируем → Тексты → Верстаем → Рисуем).
8. **Проверка перед запуском**: сводка ответов + email + оферта/согласие на рассылку.

## Тесты и защита

```bash
python3 -m pytest tests/ -q   # 45 тестов: ниши, редактор, импорт, демо-генератор, промпты, API
```

- Тесты не ходят в сеть: LLM/картинки либо выключены (чистый демо-путь),
  либо замоканы; сайты пишутся во временную папку.
- Базовая защита API: rate-limit по IP (генерация 10/час, чат 60/час,
  анализ/заявки 120/час; ответ `429`), `/api/leads` закрывается токеном
  `SITEGEN_ADMIN_TOKEN` (`?token=` или заголовок `X-Admin-Token`).
- Прогресс долгой правки: `GET /api/chat/progress/{id}` →
  `{"stage": "images", "target": "products", "done": 3, "total": 6}`;
  фронт опрашивает его, пока ждёт синхронный `/api/chat`.
- История чата персистентна (`{id}.chat.json`) — переживает рестарт сервера.

## Realtime-правки (SSE)

`GET /api/chat/stream/{id}?message=...` (EventSource): события `start` →
`progress` (`{stage, done, total, target}` на этапе картинок) → `done`
(тот же JSON, что у POST `/api/chat`) или `error`; каждые ~15 с простоя —
`ping`. Фронт использует SSE, при обрыве молча откатывается на POST + опрос
`GET /api/chat/progress/{id}`.

## Перенос любого сайта и публикация на выбор

**Вход — два пути на welcome-экране:** `Создать с нуля` (анкета) или `Перенести сайт по ссылке`.

**Импорт (`POST /api/import {url}`):**
- Вставьте `https://example.com` → фоновая задача `IMPORT_STAGES`: Загружаем → Разбираем → Переносим → Верстаем → Готовим.
- `importer.py`: SSRF-защита (режет private/local/loopback, лимит 2.5 МБ, 12 с), вытаскивает `title/h1/h2/p/phones/emails/colors/text_dump` регулярками (без bs4), LLM переписывает в нашу схему (`prompts.build_import_messages`) с фолбэком `heuristic_site` без ключа.
- Источник сохраняется (`site.import_source`), тема берётся из выбранного акцента. Дальше — тот же редактор и чат.

**Публикация — выбор на result и в редакторе (`Публикация`):**
- **Оставить на СБОРКА:** сайт уже живёт по `/api/site/{id}` (домен подключите позже, как поддомены `*.вашдомен.ru` в проде).
- **Скачать ZIP:** `GET /api/export/{id}` → `index.html` + `README.txt` (залейте по FTP на любой хостинг; сайт самодостаточен — data-URI + Google Fonts).
- **Отправить в WordPress:** `POST /api/publish/wp/{id} {wp_url, username, app_password, status}` → Basic Auth → `POST {wp_url}/wp-json/wp/v2/pages` (фолбэк на `/posts`), контент завёрнут в `<!-- wp:html -->`.

## Оценка качества (eval)

```bash
python eval.py                  # офлайн: 11 ниш, структурные метрики
python eval.py --judge           # + LLM-судья (concreteness/no_fluff/structure 1–5)
python eval.py --shots           # + скриншоты (нужен playwright + chromium)
```

Метрики: порядок секций, длина H1, детектор 10 клише, цены с цифрами,
число FAQ, форма заявки, уникальность якорей. Отчёт — `eval_reports/report.md`.
Демо-контент детерминирован: eval ловит регрессии рендера и промптов.

## Docker и прод-фундамент

```bash
cp sitegen/.env.example .env   # вписать ключи
docker compose up --build      # http://localhost:8000  (/api/health → billing_paused)
```

- Данные (`SITEGEN_DATA_DIR`, в контейнере `/data`): сайты, версии, чаты,
  заявки (`{id}.leads.json` — переживают рестарт).
- Вход по email-коду: при настроенном SMTP (`SMTP_*` в `.env`) коды
  отправляет/проверяет бэкенд (`/api/auth/code`, `/api/auth/verify`,
  кулдаун 44 с, TTL 10 мин, 5 попыток); без SMTP фронт работает в демо-режиме.
- CI (`.github/workflows/ci.yml`): pytest + `node --check` на каждый push.
